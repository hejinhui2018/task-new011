# 展位排布工作台（Booth Layout Planner）

面向会展运营团队的展位排布工具：在 20 × 14 米展厅平面图上添加、拖动、缩放、旋转矩形展位，
**搭建前**自动发现展位重叠、通道过窄、出口被堵、疏散路径不可达等问题。纯前端实现，React + TypeScript + Vite，
数据保存在浏览器本地（localStorage），**不需要后端**。

## 快速开始

```bash
npm install        # 安装依赖
npm run dev        # 本地开发，默认 http://localhost:5173
```

其他命令：

```bash
npm run build      # 类型检查 + 生产构建，产物在 dist/
npm run preview    # 本地预览生产构建
npm test           # 运行全部单元测试（Vitest，一次约 4 秒）
npm run test:watch # 测试监听模式
npm run typecheck  # 仅做 TypeScript 类型检查
```

要求 Node.js ≥ 18。

## 功能一览

- **展厅平面**：20 × 14 m，南墙（x 3~5 m）、北墙（x 14~16 m）各一个固定安全出口。
- **展位编辑**：添加、拖动、8 个控制点缩放、90° 旋转（交换宽高），所有几何变化**吸附到 0.5 m 网格**。
- **重点展位与“双通道”**：检查器里把普通展位标记为★重点展位后，系统为其寻找
  **两条通往不同出口、除接待起点外不共用任何通行网格**的疏散路线；
  并用**顶点分裂网络最大流**做全局判定（每格容量 1、每个出口容量 1），
  不会因贪心先选的某条最短路堵死第二条而误报。状态明确分为
  **双路可用（绿+蓝双线）/ 仅单路（琥珀线）/ 完全不可达**。
- **临时封控模式**：工具栏进入后可
  - **单击出口**将其临时关闭/重新开放（橙色叉，区别于展位封堵的红叉）；
  - 在画布空白处**拖出 0.5 m 网格对齐的封控区域**（橙色斜纹），点选后可删除；
  - 一键“清除封控”。
  任何封控变化后，双路状态、路线与告警**立即重算**；单路告警会标明根因是
  **出口关闭**还是**空间瓶颈**，完全断路单独提示。
- **90 秒双通道演练**：工具栏一键自动播放
  「单路（瓶颈）→ 清空封控恢复双路 → 关闭出口后降级 → 撤销恢复」，
  每一步都是真实历史操作（约 60 秒，留有讲解余量）。
- **画布缩放/平移**：滚轮以光标为锚点缩放、拖空白平移、右下角缩放按钮与“适应窗口”；
  缩放到任意倍率后，拖拽与缩放的坐标换算始终精确（世界坐标 = `(屏幕像素 − 平移) / 缩放`）。
- **撤销 / 重做 / 重置**：一次拖动或缩放只产生一条历史；支持 `Ctrl/⌘+Z`、`Ctrl/⌘+Y`（或 `Ctrl+Shift+Z`）；
  标记重点、开关出口、拖出/删除封控区域、“方案重置 / 载入示例”全部走同一条历史，可撤销恢复。
- **实时检查**（任何改动后立即重算，告警与路径同步更新）：
  - **越界**：展位超出 20 × 14 m 展厅边界；
  - **重叠**：两个展位发生面积相交，图上用红色斜纹标出重叠区域；
  - **净空不足**：正对的两边间距 < 1.5 m，图上画出带数值的尺寸标注；纯对角斜置不判定（斜角可通行）；
  - **出口被堵 / 被关**：展位压住出口开口（红叉“出口堵死”）或临时封控关闭（橙叉“临时关闭”）；
  - **疏散不可达**：普通展位从**正面接待点**（正面边中点外侧 0.25 m）在 0.5 m 网格上做 BFS，
    4 邻接、展位与封控区域为障碍，到任一开放出口无路径时告警，并区分“出口关闭 / 完全断路”。
- **告警上图 + 列表联动**：问题不只靠颜色——每个展位角上有“重/距/界/封/关/单/堵”字符徽标，
  右侧列表按严重度排序并带“出口关闭 / 空间瓶颈 / 完全断路”根因标签，
  点击任一告警会在图上高亮相关展位并选中，检查器同步显示原因与相关展位。
- **内置示例**：首次打开即载入“出口被堵”示例；另有“双通道”示例（重点展位 K01 初始仅单路）。
- **本地保存与旧数据兼容**：方案变更自动写入 `localStorage`（键 `booth-planner:plan:v1`）。
  **旧版本保存的 `{ booths }` 方案会自动迁移**（补空封控、`critical=false`），继续正常打开，
  普通展位仍按原来的单路 BFS 检查。

> 另有一类对象是**围挡（partition）**：砖纹显示，是通道障碍（参与寻路阻挡、可封出口），
> 但没有接待点、不做 1.5 m 净空检查，两面围挡允许拼接，用来搭“封闭区”这类场景。

坐标约定：所有领域计算都以**米**为单位、展厅左上角为原点（x 向右、y 向下）；
屏幕上只在根 `<g>` 做一次 `translate(pan) scale(pxPerMeter)` 仿射变换。

### 关键算法说明

- **净空判定**：只在两个矩形于某一轴投影重叠（边对边）时检查另一轴间距，
  间距 `< 1.5 m` 告警；边重合（0 间距）属重叠；两轴都有正间距是对角关系，不约束。
- **单路寻路**：0.5 m 网格（40 × 28），展位与封控区域覆盖的格子为障碍（边与格线重合不算阻挡，可贴边通行），
  从接待点对应格出发做 4 邻接 BFS，出口沿开口每 0.5 m 设一个目标格；先到的目标给出最近开放出口路径。
- **双通道判定（重点展位）**：在同一 0.5 m 网格上构造**顶点分裂有向网络**——
  每个通行格拆成 `in → out`（容量 1，接待起点格容量 2），4 邻接之间互连，
  每个出口一个容量 1 的出口节点汇入超级汇点，再从接待点超级源点做 **Edmonds–Karp 最大流**。
  - 最大流 **2** 才是双路：格容量 1 保证两条路除起点外**不共格**，出口容量 1 保证它们**通往不同出口**；
  - 这是“是否存在一组可行双路径”的**充要条件**（Suurballe/点不相交路径判定），
    因此即使“先 BFS 取最近出口最短路”会堵死第二条路（贪心陷阱），也不会误报；
  - 最大流只有 1 时，再看可达出口数：仅剩 1 个出口可到 ⇒ **出口关闭**；
    两个出口都能到却凑不出不共格双路 ⇒ **空间瓶颈**；0 ⇒ **完全断路**。
  - 带流路径通过残量网络上的逐单位 DFS 拆出，分别染成绿（主路）/蓝（备路）。
- **历史粒度**：拖动/缩放/拖封控区域过程中只更新画面（不入栈），松手时把最终结果作为**一条**快照提交。

## 数据与隐私

所有方案数据仅保存在当前浏览器的 localStorage 中，不发起任何网络请求。
清空可使用工具栏“方案重置”，或手动清除站点数据。
