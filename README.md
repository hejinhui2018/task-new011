# VenueFlow 展位排布工作台（Booth Layout Planner）

面向会展运营团队的展位排布工具：在 20 × 14 米展厅平面图上添加、拖动、缩放、旋转矩形展位，
**搭建前**自动发现展位重叠、通道过窄、出口被堵、疏散路径不可达等问题。纯前端实现，React + TypeScript + Vite，
数据保存在浏览器本地（localStorage），**不需要后端**。

## 快速开始

```bash
npm install        # 安装依赖
npm run dev        # 本地开发，默认 http://localhost:5173
```

其他命令：

```bash
npm run build      # 类型检查 + 生产构建，产物在 dist/
npm run preview    # 本地预览生产构建
npm test           # 运行全部单元测试（Vitest，一次约 4 秒）
npm run test:watch # 测试监听模式
npm run typecheck  # 仅做 TypeScript 类型检查
```

要求 Node.js ≥ 18。

## 功能一览

- **展厅平面**：20 × 14 m，南墙（x 3~5 m）、北墙（x 14~16 m）各一个固定安全出口。
- **展位编辑**：添加、拖动、8 个控制点缩放、90° 旋转（交换宽高），所有几何变化**吸附到 0.5 m 网格**。
- **画布缩放/平移**：滚轮以光标为锚点缩放、拖空白平移、右下角缩放按钮与“适应窗口”；
  缩放到任意倍率后，拖拽与缩放的坐标换算始终精确（世界坐标 = `(屏幕像素 − 平移) / 缩放`）。
- **撤销 / 重做 / 重置**：一次拖动或缩放只产生一条历史；支持 `Ctrl/⌘+Z`、`Ctrl/⌘+Y`（或 `Ctrl+Shift+Z`）；
  “方案重置 / 载入示例”本身也可撤销。
- **实时检查**（任何改动后立即重算，告警与路径同步更新）：
  - **越界**：展位超出 20 × 14 m 展厅边界；
  - **重叠**：两个展位发生面积相交，图上用红色斜纹标出重叠区域；
  - **净空不足**：正对的两边间距 < 1.5 m，图上画出带数值的尺寸标注；纯对角斜置不判定（斜角可通行）；
  - **出口被堵**：展位压住出口开口内侧网格，出口处显示红叉与“出口堵死”；
  - **疏散不可达**：从每个展位**正面接待点**（正面边中点外侧 0.25 m）在 0.5 m 网格上做 BFS，
    4 邻接、展位为障碍，到任一出口无路径时告警；可达时图上用绿色虚线画出实际可走路径。
- **重点展位“双通道”演练**：检查器里把普通展位标记为**重点展位**后，系统为它求
  **两条除接待起点外不共用任何通行格、且通往不同出口**的疏散路线（节点拆分 + 最大流全局判定，
  不会因先走的短路占了咽喉而误报）。图上同时画蓝（路线 1）/橙（路线 2）两条虚线，
  展位角标与检查器卡片明确区分 **双路可用 / 仅单路 / 完全不可达**，
  单路/断路告警还标注原因：**出口关闭、空间瓶颈、完全断路**。
- **临时封控模式**：顶部“🚧 临时封控”进入——**点击出口**开/关（琥珀色“临时关闭”横杠），
  **空白处拖出封控区域**（0.5 m 网格吸附的斜纹矩形）；再点一下已封区域可删除，“清除封控”一键撤销。
  封控一变化，双路状态、路径与告警立即重算（封控区域与展位同为网格障碍，关闭的出口从可用出口集排除）。
- **90 秒双通道演练**：顶部“▶ 双通道演练”自动播放约 25 秒的引导卡：
  ① 仅单路（挡墙堵门、空间瓶颈）→ ② 双路可用（移走挡墙）→ ③ 关闭南出口后降级（出口关闭）
  → ④ 一次撤销恢复双路；标记重点展位、添加封控、撤销/重做、恢复示例走同一条历史，状态始终一致。
- **旧数据兼容**：浏览器里只含 `{ booths }` 的旧方案直接打开，补出空封控字段、
  旧展位默认非重点（继续走原来的绿色单路检查）；损坏条目容错跳过。
- **告警上图 + 列表联动**：问题不只靠颜色——每个展位角上有“重/距/界/封/堵”字符徽标，
  右侧列表按严重度排序，点击任一告警会在图上高亮相关展位并选中，检查器同步显示原因与相关展位。
- **内置“出口被堵”示例**：首次打开即载入。左上角两面围挡与外墙合围困住 A01（不可达），
  B09 封住南出口。把“围挡-竖”拖开，A01 的绿色疏散路径会立刻出现、告警立即消失；
  拖开 B09，南出口立即解封。顶部“载入‘出口被堵’示例”可随时还原。
- **本地保存**：方案变更自动写入 `localStorage`（键 `booth-planner:plan:v1`），刷新不丢失。

> 另有一类对象是**围挡（partition）**：砖纹显示，是通道障碍（参与寻路阻挡、可封出口），
> 但没有接待点、不做 1.5 m 净空检查，两面围挡允许拼接，用来搭“封闭区”这类场景。

坐标约定：所有领域计算都以**米**为单位、展厅左上角为原点（x 向右、y 向下）；
屏幕上只在根 `<g>` 做一次 `translate(pan) scale(pxPerMeter)` 仿射变换。

### 关键算法说明

- **净空判定**：只在两个矩形于某一轴投影重叠（边对边）时检查另一轴间距，
  间距 `< 1.5 m` 告警；边重合（0 间距）属重叠；两轴都有正间距是对角关系，不约束。
- **寻路**：0.5 m 网格（40 × 28），展位与临时封控区域覆盖的格子为障碍（边与格线重合不算阻挡，可贴边通行），
  从接待点对应格出发做 4 邻接 BFS，出口沿开口每 0.5 m 设一个目标格；先到的目标给出最近出口路径。
- **双路径（重点展位）**：每个可通行格拆成容量 1 的 `in→out` 节点（接待格容量 2，允许两条路共用起点），
  相邻格互连；每个出口加一个容量 1 的“闸门”节点（保证两条路终点出口不同）。
  在该网络上跑 Edmonds-Karp 最大流，**流值为 2 才是真正双路可用**，再把整数流分解、摘除环流还原成两条格点路径。
  这是全局判定：经典“贪心先占最短路 → 误报单路”的场景（凹室咽喉）也能正确找到双路，测试中有反例。
  降级原因通过“忽略临时关闭出口再算一次”的对照诊断区分为出口关闭 / 空间瓶颈 / 完全断路。
- **历史粒度**：拖动/缩放过程中只更新画面（不入栈），松手时把最终结果作为**一条**快照提交。

## 测试

  旋转、正面接待点；
- `pathfinding.test.ts`：空厅可达、路径 4 邻接且不穿障碍、四面围挡封闭时不可达、
  打开缺口后必须绕行、一个出口被封仍可去另一出口、出口封堵展位识别；
- `dualpath.test.ts`（新）：双路除起点外格点不相交且终点为不同出口、
  **贪心反例**（最短路先占凹室咽喉会误判单路，最大流仍找到双路）、共用咽喉时仅单路、
  单出口闸门限 1、起点封死 flow=0、展厅级空厅双路/关一出口单路/封控区困住/封门降级与撤销恢复；
- `dual-validation.test.ts`（新）：分析层的双路/单路/断路状态与三类原因、
  普通展位仍走单路检查、封控增量重算，以及演练四步状态序列用 History 完整复刻并验证撤销/重做恢复；
- `persistence.test.ts`（新）：旧 `{booths}` 存档迁移（默认非重点、补空封控）、
  新版往返一致、脏数据容错、损坏 JSON 不抛异常；
- `history.test.ts`：提交/撤销/重做、分支丢弃 redo 栈、相等状态不入栈、容量淘汰、重置；
- `validation.test.ts`：端到端分析（重叠/净空/越界/围挡拼接），以及内置示例的三条关键断言——
  初始仅“南出口被封 + A01 不可达”、拖开围挡后 A01 立即恢复路径、拖开 B09 后南出口立即解封。

## 数据与隐私

所有方案数据仅保存在当前浏览器的 localStorage 中，不发起任何网络请求。
清空可使用工具栏“方案重置”，或手动清除站点数据。
